### **从零开始的Analysis Production**

Analysis Production（下称AP）工作流主要按照如下方式工作：

1. 你需要创建一个合并请求(merge request)到[lhcb-datapkg/AnalysisProductions](https://gitlab.cern.ch/lhcb-datapkg/AnalysisProductions/)，添加你的选项和相关的数据。

2. 当你的合并请求被接受并合并之后，Production会被提交到LHCbDIRAC.

3. Production会在DIRAC转换系统上运行，可以在[Analysis Production webpage](https://lhcb-productions.web.cern.ch/ana-prod/productions)监管进度。

4. 当转换结束后，输出的数据可以在CERN EOS上获取。

#### Creating an Analysis Production

创建一个新的AP，需要将仓库克隆到lxplus上并创建一个新的分支：

```
git clone https://gitlab.cern.ch/lhcb-datapkg/AnalysisProductions.git
cd AnalysisProductions
git checkout -b ${USER}/my-analysis
```

其中```${USER}```可以用```echo ${USER}```查询，```git branch```可以查看现在有哪些分支以及目前处于哪个分支。

接下来需要创建一个包含我们接下来需要添加的新的Production的所有内容的文件夹。文件夹命名为你的数据样本将被分类的区域。文件夹中需要包含你所需要的DaVinci option file，以及一个```.yaml```文件用于配置所有的工作。```.yaml```文件示例如下：

```yaml
defaults:
    application: DaVinci/v46r11
    wg: BnoC
    automatically_configure: yes
    turbo: no
    options:
        - data_options.py
    inform:
        - yilinl
    output: Bd2Ksthh.ROOT

B02DpiD2hhh_15_MagDown:
    input:
        bk_query: /LHCb/Collision15/Beam6500GeV-VeloClosed-MagDown/Real Data/Reco15a/Stripping24r2/90000000/BHADRONCOMPLETEEVENT.DST
```

#### Testing your productions locally

LbAPLocal是一个用于对AnalysisProductions运行offline测试的python库, 在lxplus上的LHCb环境下默认安装了LbAPLocal，通过CVMFS可以配置LHCb环境：

```bash
source /cvmfs/lhcb.cern.ch/lib/LbEnv
```

在本地进行测试之前，需要确保如下内容：

- **CVMFS**: ```/cvmfs/lhcb.cern.ch```仓库已安装好且可使用；
- **Grid proxy**: 查询DIRAC需要有效的LHCb网格代理；可以通过如下命令配置:
  ```bash
  lhcb-proxy-init
  ```

- **AnalysisProductions repository**：大多数命令需要在一个AnalysisProductions的仓库里运行

一个典型的本地测试工作流如下

```bash
# 1. Clone the repository (auto-detects best auth method)
lb-ap clone my-feature-branch

# 2. List available productions
lb-ap list

# 3. List jobs for a specific production
lb-ap list MyAnalysis

# 4. Validate the configuration first (dry-run)
lb-ap test MyAnalysis My2016MagDownJob --dry-run

# 5. Run the full test
lb-ap test MyAnalysis My2016MagDownJob
```
